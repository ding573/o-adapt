# Evaluation explainer

The evaluation is split so candidate feasibility, generated points, model route selection and human training-quality judgement are not collapsed into one headline score.

## Deterministic route evaluation

| Command | Fixture | Output | Meaning |
|---|---|---|---|
| `npm run evaluate` | `cases.json` | `results.json`, `RESULTS.md` | 20 normal existing-control requests and 10 edge cases |
| `npm run evaluate:explore` | `explore-cases.json` | `explore-results.json`, `EXPLORE_RESULTS.md` | Six generated-point requests and four exploration edge cases |
| `npm test` | Code assertions | Terminal pass/fail | Retrieval, verification gates, determinism, invalid input, HTTP and adapter regression |

Expected outcomes were fixed in the fixture files before their recorded runs. The route oracle independently checks all-pairs spacing with haversine distance. It does not independently recompute every graph path distance or establish outdoor safety.

`RESULTS.md` includes a 20-row binary acceptance checklist. For each normal request it reports whether a route was produced and whether recorded path reachability, control verification, spacing, +/-10% distance tolerance and hazard review passed. It reports **complete pass** separately from **contract pass**, so a safe abstention is recognised as correct behaviour without being counted as a usable route.

## Live model route evaluation

`npm run evaluate:live` sends the 17 successful existing-control requests to `/api/generate`. For each request, the server supplies the model with up to 12 constraint-valid candidates and retrieved evidence. The runner records the selected route, contract checks, difference from the deterministic top candidate, tokens, provider-reported cost and latency in `live/route-comparison.json`. The `.env` file is excluded from the repository.

`live/route-human-review.json` contains five rated selected routes. `npm run evaluate:route-human` validates the entries and regenerates `live/route-human-review-results.json` and `live/ROUTE_HUMAN_REVIEW_RESULTS.md`. These qualitative ratings cannot be inferred from constraint checks. The earlier explanation-only A/B and judge files are retained as development history; they do not evaluate the final architecture.

## Different-model holdout and judge

`holdout/cases.json` contains 20 requests generated by `google/gemini-2.5-flash` without access to the original fixtures or route outputs, then frozen before evaluation. Its SHA-256 and generation prompt hash are in `holdout/generation-metadata.json`. The request set is independent of the production route-selector's original fixtures, but has no external human feasibility labels. `npm run evaluate:holdout` runs the existing engine and `openai/gpt-4o-mini` selector, checks recorded objective constraints, then asks Gemini to compare only differing selected and baseline routes in blinded A/B order. It writes `holdout/results.json` and a 20-row `holdout/RESULTS.md`. It resumes saved rows and does not regenerate the frozen requests. The optional generator is `holdout/generate.mjs`; it refuses to overwrite the fixture.

`npm run evaluate:holdout:calibrate` has Gemini score the five existing human-reviewed routes without receiving the human scores. The comparison appears in `holdout/calibration.json` and `holdout/CALIBRATION.md`. Both live commands require the local OpenRouter key and incur API charges; the saved outputs are already included. Do not rerun merely to inspect them.

## Recorded headline metrics

- Existing controls: 17/20 verified courses; 30/30 behavioural contracts.
- Exploration: 6/6 virtual-control routes on path nodes I verified; 4/4 edge abstentions; 10/10 contracts.
- Live model routes: 17/17 successful selections and 17/17 deterministic contract passes; 15/17 differed from the deterministic top candidate; 37,750 tokens; US$0.00602205; 1.74 s average latency.
- Human route-quality review: 5 cases; mean request fit 4.60/5, mean training-focus fit 4.40/5, and supported selection reason 4/5. N03 exposed a difficulty-classification weakness.
- Different-model holdout: 18/20 routes generated, 18/18 selected routes passed the recorded objective checks, and 10/18 differed from the deterministic baseline. In 10 blind comparisons Gemini preferred the selected route 3 times, the baseline 4 times and tied 3 times; mean focus-fit scores were 3.70/5 for both. Eight pairs were identical and not judged.
- Judge calibration on the five earlier human-rated routes: mean absolute score difference 0.40/5 for request fit and 1.20/5 for training-focus fit; reason-support agreement 2/5.

## Limitations

The original predefined fixtures were fixed before their recorded run. The later holdout is generated by a different model, not collected from independent people; it tests the production selector on unseen requests but supplies no ground-truth outdoor feasibility or route-quality labels. Gemini's own judgements are not a reliable substitute for expert review: its five-case calibration disagreed with the human review, and some holdout reasons inferred physical training value from feature names alone. The original human review uses one reviewer and is not a blinded paired comparison with the deterministic baseline. Operational success and constraint compliance do not prove that the model chose the best training route. Exploration results remain separate because virtual GPS controls measure a different mode from the existing physical-feature controls.
